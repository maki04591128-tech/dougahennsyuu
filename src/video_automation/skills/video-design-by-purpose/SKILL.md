# 用途に合った動画デザイン（センスの底上げと、別用途の混入防止）

「センスが良い」画面は、才能より **原則（揃える・まとめる・繰り返す・差をつける）と、用途に合った型の徹底** でできている。
このスキルは ①どの動画にも効く原則 ②用途ごとの型（使ってよい部品・数値）③別用途の部品が混ざらないようにする判定手順 ④点検表 をまとめる。
演出（動き）の具体は `blender-rich-screen-direction` と `blender-video-motion-design` を使うが、**どの演出を使ってよいかはこのスキルの用途の型が決める**。

---

## 1. どの用途にも効く原則

### 1.1 四つの原則（近接・整列・反復・対比）
| 原則 | 画面での意味 | よくある失敗 |
|---|---|---|
| 近接 | 関係するもの（見出しと本文、ラベルと数値、話者名と台詞）は近く、関係ないものは離す | 見出しと本文の間隔が、本文と次の項目の間隔と同じ |
| 整列 | 左端・中心線・下端など **基準線を 1 つ決めて** そろえる。間隔（アキ）も同じにする | 何でも中央揃え。要素ごとに左端がずれる |
| 反復 | 同じ役割の要素は動画全体で同じ見た目（色・書体・位置・動き） | 章ごとにカードの形や色が変わる |
| 対比 | 重要度の差をはっきり付ける（大きさ 1.5 倍以上・太さ・色） | 見出しと本文の大きさがほぼ同じ。全部が強調色 |

### 1.2 視線と余白
- 1 画面の主役は 1 つ。最初に見せたい物を一番大きく・一番コントラストを高く
- 横長の画面は左上から読まれやすい（F 字）。日本語の横書きの情報は左揃えが基本、題名・一言は中央も可
- 余白は「無いもの」ではなく「まとまりを作る道具」。外周の余白（タイトルセーフ）は 16:9 で画面の 5〜10%
- 画面の半分以上が無地のまま、という空きすぎも物足りなく見える。要素を大きくするか配置で埋める

### 1.3 文字（日本語）
- 読ませる文字は太めのゴシック（UD 系・Noto Sans JP・BIZ UD ゴシックなど）。装飾的な書体は「ここ」という一点だけ
- 書体は 1 本の動画で 2 種類まで（本文用＋見出し・強調用）。太さ違いで差を作る
- 字幕の目安: 1 行 13〜16 字・最大 2 行、表示は 1 秒 4 字前後
- 文字サイズは段階を決めて使い回す（例: 本文 1、見出し 1.5、題名 2.25、注記 0.75。比 1.5 の段）
- 白文字＋暗い縁取り、または半透明の帯で背景から分離する。帯は必要な高さだけ（画面の 3 割を覆う帯は重い）

### 1.4 色
- 役割で決める: ベース（背景・面）70%／メイン（見出し・面の主色）25%／アクセント（強調だけ）5%
- 色相は 3 つ程度まで。話者の色・図表の色も、この 3 色の明暗違いで作る（別の色相を足さない）
- 原色の既定値（#3399FF・#FF9933 など）はそのまま使わない。彩度と明るさを揃える
- 文字と背景のコントラストは 4.5:1 以上（WCAG AA を目安に）。色だけで意味を伝えない（形・位置・ラベルも併用）

### 1.4.1 実機で分かった色と文字の落とし穴
- **明るい背景の型（講義・子ども向け）**: 暗い文字に黒の縁取りを付けると字が潰れる。縁取りは背景の明るい色にし、話者名の縁取りも同じ色にする
- **Blender に色を渡すときは sRGB→線形に変換する**（マテリアルの色は線形）。変換しないと暗い色が浮いて灰色に見える
- 題名・カード・図表の書体は型の見出し書体に揃える（例: 解説・講義は BIZ UD ゴシック）。UDP と UD は同じ書体として数える

### 1.4.2 図表・数値（インフォグラフィック）
- 数値は正確に: 出典・単位・期間を出す。架空の値は「仮データ」と明記。数値を作らない
- 棒グラフの基準はゼロから。対数など非線形の軸は表示する
- 単位は記号で短く（ギガパスカル→GPa、パーセント→%）
- 最後に全データを読める静止の時間を作る。色だけで区別しない（ラベル・形も）

### 1.5 情報を教える動画の原則（Mayer のマルチメディア学習原則）
- 一貫性: 内容に関係ない装飾・画像・効果は入れない
- 信号: 大事な所だけ目印（色・枠・矢印）を付ける
- 冗長を避ける: 話している言葉をそのまま大きな文字で重ねない（字幕は別。カードは要点だけ）
- 空間的近接: ラベルは図の該当部分のすぐ横に
- 時間的近接: 話すのと同時に図を出す

## 2. 用途ごとの型

### 2.0 用途の一覧（22 種・4 系統）。実装は dougahennsyuu の `services/design/profiles.py`
下の 2.1〜2.2 は系統の代表（subtitle=落ち着いた系、explainer=情報系、short=勢い系、mv_pv=表現系）。各用途は系統の既定値に差分を重ねる。
| 系統 | 用途（キー） | 系統の差分の要点 |
|---|---|---|
| 落ち着いた系（動き 0） | 字幕動画 `subtitle`／インタビュー `interview`／ドキュメンタリー `documentary`／朗読・物語 `story`／ポッドキャスト `podcast` | interview・documentary は名前・肩書きの帯を制限なし。documentary は章ラベル・黒帯可。story は話者名なし・立ち絵と画像可 |
| 情報系（動き 1） | 解説 `explainer`／講義 `lecture`／操作説明 `tutorial`／料理 `recipe`／ニュース `news`／会社紹介 `corporate` | explainer のみ図形転換 8・揺れ 3・効果音 12。lecture は明るい紙面＋UD 書体 1 種。news は 2 色相・強調テロップ／キャラ不可。corporate は図形転換 6・キャラ不可 |
| 勢い系（動き 2〜3） | 縦型ショート `short`（9:16）／ゲーム実況 `game`／Vlog `vlog`／ランキング `ranking`／商品紹介 `product`／PR `promo`／イベント `event`／子ども向け `kids` | vlog・event はカード・図表なし、拍カット可。kids・vlog はフラッシュ・グリッチ不可。product はグリッチ不可・フラッシュ 2 |
| 表現系（動き 4） | MV `mv`／リリック `lyric`／予告編 `trailer` | 字幕・カード・図表なし（歌詞に置換）。trailer は歌詞なし・字幕 3 回まで・効果音可 |

判定の語の例: 「解説・教えて・ずんだもん」→explainer、「講義・スライド・研修」→lecture、「使い方・手順・画面録画」→tutorial、「実況・攻略」→game、「レビュー・開封」→product、「予告・ティザー」→trailer。「字幕を付けて」は他の用途の語があればそちらを優先する。

**画面録画を使う操作説明（tutorial）・解説（explainer）は、強化版の演出を既定にする**: 操作箇所へのズーム（クリック・画面が変わった所に寄り、待ち時間は引く）、カーソルの光とクリックの波紋、章カード・見出しの帯・進み具合の棒、BGM（声の区間は声のピークより 20dB 下、台詞の間は 7dB 上げる）と効果音 2 種（クリック・章の切り替え）、同じ作者のフリー立ち絵（話者の強調と口の開閉）、文のつながりを守る字幕。録画に字幕を付けただけの状態は「演出が弱い」。詳しい数値は `screen-tutorial-direction`。

| 用途 | 主役 | 雰囲気 | 動きの強さ |
|---|---|---|---|
| `subtitle` 字幕動画（会話・インタビュー・Vlog・朗読） | 映像と話者。文字は読ませるためだけ | 静か・邪魔しない | 0〜1（フェードのみ） |
| `explainer` 解説（キャラ掛け合い・教育・紹介） | 図・要点カード・字幕 | 明快・整理 | 1〜2 |
| `short` ショート縦動画（9:16） | 大きな要点テロップ・顔 | テンポ・強弱 | 2〜3 |
| `mv_pv` MV・PV・リリック | 歌詞・映像・光 | 世界観・表現 | 3〜4 |
| `news` ニュース・情報番組風 | 事実・数値・出典 | 信頼・中立 | 0〜1 |
| `promo` PR・商品紹介・告知 | 商品・利点・行動の呼びかけ | 印象・ブランド | 2〜3 |

### 2.2.1 背景だけの時間・字幕の速さ・歌詞
- **背景だけの時間の上限**: 情報系 10 秒・勢い系 5 秒（落ち着いた系・表現系は制限なし）。図やカードは次が出るまで残して空白を埋め、残った空白は検査で警告する。図の素材に長さの上限があるときは、消える前にフェードし、空白は実際に出した区間で数える
- **字幕の速さ**: 音声に合わせた字幕は、元の音声の速さの 1.25 倍まで（上限 1 秒 12 字）を許す（音声と同時に聞けるため）。音声に合わせていない字幕は型の「読める速さ」（情報系 1 秒 7 字など）で判定する。行の終わりの字幕は次の字幕まで最大 0.5 秒残す
- **字幕の行数・字数は型から**: 生成時に指定が無ければ型の値（歌詞は 1 行 20 字）
- **話者の区別は書体と色で（名前は出さない）**: 話者が 2 人以上なら、どの型でも話者ごとに書体・文字色・縁取りを変える。字幕の上に名前を出すのは、ニュースの肩書きなど名前そのものが情報になる場合だけ
- **書き出しの画面演出は「自動」が既定**: 用途の型で許される最も強い演出（字幕動画・インタビューなど落ち着いた系は付けない、MV・予告編は派手まで）
- **字幕の切れ目は文のつながりで決める**: 1 枚に収まる文は 1 枚で出す。収まらない文は「、」などの意味の切れ目で分け、1 行の 1/3 未満の短い切れ端（「見つかるわ」だけ等）や、「名前」と助詞の間（「VideoAutomation」｜の）で切らない
- **字幕は 1 枚に 1 文**: 次の文の頭（「実は、」など）を前の字幕の終わりに残さない。改行・切れ目は文節（「八合目より｜上は」ではなく「八合目より上は」がつながる単位）の境目だけにし、英単語・数字＋単位の途中で切らない
- **歌詞（MV・リリック）**: 字幕を使わず歌詞を使う型では、行を歌詞として出す（帯・話者名なし、見出し書体で大きめ、ゆっくりのフェード、型の主色の光のにじみ）。検査では「歌詞」の部品として数える。歌から作るときは文字起こしの時刻を使い、正しい歌詞の文を渡して時刻だけを借りる
- 話者名を使わない型（子ども向け・MV など）では話者名を出さない

- **MV・PV・予告編・PR で写真を並べるだけにしない**: 写真を置いて寄るだけの場面は 2 場面続けない。場面ごとにタイポグラフィ・モーショングラフィックス・3D・モンタージュ（画面分割・マッチカット）を主役にする（`advanced-motion-techniques`）。写真の内容が曲や台本と合わなければ写真を使わない
- **背景を平らな単色にしない**: グラデーション＋ゆっくり動く図形、流れる模様、ぼかした写真、3D の奥行きのどれかを入れる（主役より暗く・遅く）
- **図・文字に光や撮影処理をかけない**: ブルーム・ビネット・光の漏れは MV・PV・予告編・PR の強調箇所だけ
- **配置は領域で予約する**: 立ち絵・字幕・テロップ・カードの重なりと立ち絵の見切れを防ぐ領域の数値は `layout-no-overlap`

### 2.3 縦動画（short）の安全範囲
1080×1920 で、上 150〜250px（ステータスバー・検索）、下 350〜420px（キャプション・ボタン）、右 120〜150px（いいね等のボタン列）には文字・顔を置かない。

## 3. 別用途のデザインを混ぜない（判定と止め方）

### 3.1 用途を決める（指示文から）
1. 指示文にある明示の語で決める（優先）: 「MV」「PV」「歌詞」→ mv_pv／「ショート」「縦」「TikTok」→ short／「ニュース」「速報」→ news／「解説」「教える」「紹介して（概念）」→ explainer／「字幕を付けて」「文字起こし」「インタビュー」→ subtitle／「宣伝」「告知」「CM」→ promo
2. 明示が無ければ素材で推定: 音楽だけ＋歌詞→mv_pv、会話の録画→subtitle、台本＋キャラ→explainer
3. **確信が持てないときは尋ねる**。尋ねられない（無人実行）ときは、候補のうち **動きの強さが最も低い型** を選び、そう判断したことを記録する（強い演出を誤って付けるより、控えめで外す方が害が小さい）
4. 「解説動画だけど MV っぽく」のような **混ぜる指示が明示されたときだけ** 例外を許し、許した部品を一覧で記録する

### 3.2 書き出す前の検査（ガード）
実装: dougahennsyuu の `services/design/guard.py`。演出の適用時に作った部品を記録し、書き出しの要求時に検査する。error（使わない部品・回数超過・縦横の不一致）は書き出しを止め、ユーザーが明示したとき（`allow_design_violations` か extras）だけ通す。LLM 経由では例外にしない。warning（色相数・書体数・字幕の基準外・安全範囲）は結果に出す。
作った要素すべてに「部品の種類」と「どの用途の型から来たか」を付けておき、書き出す前に次を調べる。1 つでも当てはまれば **書き出さずに止めて、何が混ざったかを報告する**（自動で消してよいのは、明らかな装飾だけ）。
- [ ] 許可表で × の部品が入っていないか（例: subtitle に図形トランジション・グリッチ・揺れ）
- [ ] △ の部品が回数の上限（1〜2 回）を超えていないか
- [ ] 色が型のパレット外ではないか（色相数の上限）
- [ ] 書体が型の指定外ではないか（書体数の上限）
- [ ] 動きの強さが型の上限を超えていないか（揺れ・フラッシュ・パンチの有無、動きの長さ）
- [ ] 文字の大きさ・字幕の 1 行の文字数・表示時間が型の範囲内か
- [ ] 安全範囲（タイトルセーフ／縦動画の UI 範囲）に文字が入っていないか

### 3.3 よくある混入
| 混入 | なぜ悪いか | 正しくは |
|---|---|---|
| 字幕動画に章ラベル・パネル転換・揺れ | 話者と映像から注意を奪う | 字幕だけ。強調は文字の太さ・色だけ |
| 解説動画にグリッチ・フラッシュ | 内容と関係ない刺激（一貫性の原則に反する） | 図の出し方とカードの順番で見せる |
| MV に箇条書きカード・字幕帯 | 世界観を壊す・説明的になる | 歌詞をキネティック文字で |
| ニュースにポップな書体・跳ねる動き | 信頼を損なう | UD ゴシック・直線的な押し出し |
| ショートに 16:9 の配置そのまま | UI に隠れる・文字が小さい | 安全範囲内に大きく |

## 4. センスの点検表（書き出した画を見て）
- [ ] 一目で主役が分かる。2 番目、3 番目の順も分かる
- [ ] 基準線がある（左端・中心線）。同じ間隔が繰り返されている
- [ ] 同じ役割の要素が動画全体で同じ見た目
- [ ] 色相 3 つ以内、強調色は 5% 程度の面積だけ
- [ ] 書体 2 種類以内、文字サイズは決めた段だけ
