# VideoAutomation 運用ガイド

日々の運用、バックアップ、更新、トラブル対応をまとめています。使い方は [USER_MANUAL.md](USER_MANUAL.md) を参照してください。

## 1. フォルダ構成

インストール先（既定は `%LOCALAPPDATA%\VideoAutomation`）の構成:

| パス | 内容 |
|---|---|
| `.venv\` | Python と依存パッケージ（再インストールで作り直す） |
| `src\` | アプリ本体 |
| `.env` | 設定（`VA_` で始まる環境変数と同じ。更新しても残る） |
| `data\database\app.db` | プロジェクト・台本・タイムライン・承認・履歴・品質検査結果（SQLite） |
| `data\projects\<ID>\` | 取り込んだ素材・音声・書き出した動画・字幕 |
| `data\logs\` | ログ（JSON 形式。API キーは記録しない） |
| `data\cache\` | プレビュー画像・検索結果のキャッシュ（消しても再作成される） |

## 2. 主な設定（`.env`）

| 変数 | 既定値 | 説明 |
|---|---|---|
| `VA_DATA_DIR` | インストール先\data | データの置き場所 |
| `VA_PORT` | 8765 | 内部 API のポート（127.0.0.1 のみで待ち受け） |
| `VA_OLLAMA_URL` / `VA_LMSTUDIO_URL` | 127.0.0.1:11434 / :1234 | ローカル LLM |
| `VA_VOICEVOX_NEMO_URL` / `VA_VOICEVOX_URL` | 127.0.0.1:50121 / :50021 | 音声合成エンジン |
| `VA_FFMPEG_PATH` / `VA_BLENDER_PATH` | 自動検出 | 実行ファイルの場所 |
| `VA_ACESTEP_PATH` | なし | ACE-Step 1.5 のフォルダ（BGM 生成） |
| `VA_SINGLE_LOADED_MODEL` | true | LLM を 1 つずつ読み込む（VRAM 8GB 向け） |
| `VA_IMPORT_DIRS` | ビデオ・ピクチャ・ミュージック・ダウンロード・デスクトップ | 素材を取り込めるフォルダ（JSON 配列。例 `["D:/素材"]`） |
| `VA_PEXELS_API_KEY` など | なし | 素材サービスの API キー（UI で登録した場合は暗号化して DB に保存） |

設定を変えたらアプリを再起動します。

## 3. バックアップと復元

- **バックアップ:** アプリを終了してから `data` フォルダと `.env` をコピーします。
  DB だけなら `data\database\app.db`、動画・素材も含めるなら `data\projects` もコピーしてください。
- **復元:** アプリを終了し、コピーしておいた `data` と `.env` を元の場所に戻します。
- 素材サービスの API キーは Windows の DPAPI で暗号化しています。**別の PC・別のユーザーでは復号できない**ため、
  移行先では UI から登録し直してください。

## 4. 更新

1. 新しい配布 zip を展開し、`install.bat` を実行します（データと `.env` は残ります）。
2. DB に新しい列が必要な場合は、起動時に自動で追加されます。
3. 念のため、更新前に「3. バックアップ」を行ってください。

## 5. 定期的に行うこと

| 頻度 | 作業 |
|---|---|
| 公開前ごと | 品質検査タブで「要修正」が 0 件であることを確認する |
| 公開前ごと | 素材・BGM タブの「クレジットを表示」を概要欄に記載する |
| 月 1 回程度 | `data\logs` と `data\cache` の古いファイルを整理する |
| モデルを入れ替えたとき | LLM設定タブで「検出」と推論テストを行い、タスク割り当てを見直す |

## 6. トラブル対応

最初に `.venv\Scripts\video-automation.exe --doctor` を実行し、どのエンジンが使えないかを確認します
（`--doctor --json` で詳細）。

| 症状 | 原因と対処 |
|---|---|
| 書き出し・プレビューができない | FFmpeg が見つからない。PATH に入れるか `VA_FFMPEG_PATH` を指定 |
| 「no_llm_available」と出る | Ollama / LM Studio が起動していない、またはモデルが無い。起動して LLM設定タブで「検出」 |
| 「llm_output_invalid」と出る | モデルが指定の形式で答えられなかった（1 回は自動で再試行済み）。もう一度実行するか、AIアシスタントで別のモデルを選んで「やり直す」 |
| AI の生成が遅い | 初回はモデルの読み込みに時間がかかる。VRAM が足りないと CPU 実行になり遅くなる |
| 音声が生成できない | Nemo / VOICEVOX が起動していない、または台本のキャラクターに話者 ID が無い |
| 文字アニメーション・図表が作れない | Blender が見つからない。`VA_BLENDER_PATH` を指定 |
| BGM 生成が止まる | VRAM 不足。ACE-Step は補助 LM を読み込まない設定（`ACESTEP_INIT_LLM=false`）で起動する |
| 素材検索で Pexels 等が出ない | API キーが未登録。素材・BGM タブの「APIキー設定…」で登録 |
| AI の提案が反映されない | 承認待ちのまま。AIアシスタントの「承認待ち」または編集・書き出しタブで承認する |
| 台本修正案を承認できない（409） | 提案の後に台本が変わった。もう一度生成し直す |
| 品質検査で「黒画面」 | 映像の無い区間がある。背景素材を置くか、意図した暗転なら問題なし |
| 品質検査で「ラウドネス」 | 書き出し時の音量正規化を外した、または BGM が大きい。音量を調整して書き出し直す |

## 7. セキュリティ

- 内部 API は 127.0.0.1 でだけ待ち受けます。外部に公開しないでください。
- LLM には任意のコマンド・コードの実行やファイルへの自由なアクセスを許可していません。
  編集はすべて共通の命令形式で検証し、変更を伴う操作は承認が必要です。
- 素材の取り込みは https のみで、許可したホストからだけ取得します（社内ネットワークのアドレスには接続しません）。
- 素材の取得元・取得日時・ライセンス条件はスナップショットとして保存し、後から確認できます。

## 8. 開発者向け

```powershell
uv sync --extra ui                 # 開発環境
uv run pytest                      # テスト（外部エンジンは偽物、FFmpeg は実物）
$env:VA_LIVE_TESTS="1"; uv run pytest tests/live -s   # 実機テスト（Ollama・Nemo・Blender 等）
uv run python tools/build_release.py                   # 配布 zip（dist\）
```
